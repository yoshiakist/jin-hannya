# 深般若 — Graphical Heart Sutra Explorer

般若心経を「文字 → 句 → 語 → 構成要素」と際限なく潜っていける、グラフィカルな訳文兼辞書。
サイトの探索自体が瞑想体験になる UI を目指す。

> 本ドキュメントは `prompts/001.md`（企画）と `sample_image/*.png`（PC モック 3 枚）の分析結果をもとに、
> 実装に必要な情報をまとめたものである。経文本文・解説文本文は本ドキュメントには含めず、
> `content/` 配下のデータとして管理する（→ [コンテンツモデル](#コンテンツモデル)）。

## 体験の骨格

1. 経文全体がほんわかと浮かんでレンダリングされ、各文字が微妙にゆらいでいる。
2. ある句に hover すると、その範囲の文字がフォーカスして明るくなる。
3. クリックで他の文字が退き、その句へズームイン。訳と解説が現れる。
4. 句の中の語に hover すると構成要素がふわりと周囲に並び、クリックでさらに一段潜る。
5. 以下、あらゆるレイヤー・あらゆる詳細度の用語で同じ操作が反復される。

全遷移はふんわりと滑らかに接続し、その間 BGM は途切れず鳴り続ける。

### 用語: 深度と性能ティアを混同しない

本ドキュメントでは 2 種類の「段階」が登場する。衝突を避けるため呼称を固定する。

| 呼称 | 意味 | 例 |
|---|---|---|
| **深度 `L0` / `L1` / `L2` …** | グラフを潜った階層。ユーザーの現在位置 | `L0` = 全文の紙面、`L1` = 句、`L2` = 句、`L3` = 語 |
| **性能ティア `Tier 1` / `Tier 2` / `Tier 3`** | 実行環境の描画能力 | `Tier 1` = WebGPU、`Tier 2` = WebGL2、`Tier 3` = WebGL 不可 |

「Tier」は性能の話にのみ使う。階層の話には使わない。

### 状態機械

ズーム中の多重クリックを殺すため、遷移相を明示的に持つ。

```
idle ──hover──▶ hovered ──click──▶ zooming-in ──▶ focused
  ▲                                                 │
  └──────────── zooming-out ◀──back / breadcrumb ────┘
```

`zooming-in` / `zooming-out` の間は入力を無効化する。`focused` からの子ノードへの遷移も同じ相を通す。

## モック分析

`sample_image/img_01.png` `img_02.png` `img_03.png`（いずれも 16:9 / PC 想定）から読み取った画面文法。

### 3 枚に共通するフレーム

縦書きの読み順に従い、**情報は右から左へ流れる**。右が「今いるノード」、左が「その詳説」。

| 位置 | 要素 | 備考 |
|---|---|---|
| 画面右端 | 現在ノードの大書（筆文字・縦組み） | 画面の主役。高さは画面の 60〜85% を占める |
| 大書のすぐ左脇 | 読み（かな）／梵語（カナ + ラテン翻字） | 極小サイズ・字間広め・縦組み |
| 右 1/4 付近 | 短い定義（サマリー） | 縦書き 2〜4 列、数十字 |
| 中央 | 子ノードの関係図 | ノードによって配置文法が変わる（後述） |
| 左 1/3〜1/2 | 長文解説 | 縦書き多列。列は右から左へ進む |
| 右上 | 「読み上げ」ボタン | ピル型の枠線 + スピーカーアイコン |
| 左下 | 左矢印 `←` | 「左にまだコンテンツがある」の示唆。細い白線の矢印のみ |

- 背景はほぼ完全な黒。要素間の余白が非常に大きく、密度は低い。
- 大書と中央の図は、**白い細い引き出し線**で結ばれる（img_03 で顕著。水平 → 段差 → 図の外周へ接続）。親子関係を視覚的に明示する装置。
- カーソル位置には通常のマウスポインタが表示されている（カスタムカーソルではない）。

### レイアウト文法は 3 種類ある

企画で言う `layout` ヒントは、モックから少なくとも次の 3 つが確認できる。

| ヒント | 出典 | 見た目 |
|---|---|---|
| `none` | img_01 | 子の図を持たず、大書とテキストのみ。句レベルのノード |
| `circle` | img_03 | 筆で描いた**円相**の内側に、子要素を円周上へ均等配置 |
| `column` | img_02 | **角丸矩形**のノードを縦に並べ、細い縦線で直列に連結 |

### img_01 — 句レベル（`layout: none`）

- 大書は 1 ノード分の語ではなく**句全体**を 2 列に折り返して大書する。
- 大書の左に読みガナが縦一列。さらに左に短い訳文、その訳文の下端に**淡いオレンジ寄りの細い縦罫**が入り、区切りとして働く。
- 中央〜左は解説の多列組版のみ。図は無い。

### img_03 — 円相レイアウト（`layout: circle`）

- 中央に、筆のかすれ・にじみを持つ**手描き感のある円**（正円ではなく、線幅が場所によって変わる）。直径は画面高の約 6 割。
- 円の内側に子 5 要素の筆文字を円周上へ配置。頂点付近から時計回りに 1 つずつ。中心は空。
- hover 中の 1 要素だけが**琥珀色に発光**し、他は白のまま。発光は文字の輪郭からにじみ出るソフトグロー。
- 円の中心は画面中央よりやや左（右端の大書ぶんオフセットされている）。

### img_02 — 縦連結レイアウト（`layout: column`）

- 角丸矩形（角丸半径は高さの約 1/4、いわゆるスタジアム形に近い）を 4 つ縦に等間隔配置。枠線は細い白、塗りは背景と同じ黒。
- 矩形どうしは**中央を通る 1 本の細い縦線**で連結。
- 最下段が hover 状態で、**文字と枠線の両方が琥珀色に発光**している（img_03 は文字のみの発光。枠を持つ図では枠も光らせる）。
- このノードでは大書からの引き出し線は見当たらない。`layout: column` では省略される、もしくは図の右上から伸びる仕様と解釈できる。

## ルート画面（全文格子）

モックに該当画面が無いため、ここで仕様を定める。

### メタファー: 写経の紙面

格子レイアウトの由来は**写経の紙面**である。この一点が以降の判断すべての根拠になる。

- 均質な升目に文字が整然と収まっている状態そのものが、第 1 層の絵になる。
- だから意味による分節をしない。写経の紙面に意味の区切りは書かれていない。
- だから紙面は画面に収まらない。**紙は画面より大きい**のが自然な状態である。

### 格子の組み方

- 全文を **16 文字で改行し続ける格子**として配置する。
- 意味による改行・分節は**行わない**。等間隔の格子を機械的に敷き詰める。
- 行数は文字数を 16 で割った値（データから導出。ハードコードしない）。最終行は端数のまま左寄せせず、行頭から詰める。
- 縦組みの読み順に従い、**列は右から左へ、文字は上から下へ**進む。1「行」= 縦 1 列。
- 字送り・行送りは等間隔。各文字は基準位置から微小にゆらぐ（→ ゆらぎは GPU 側）。

### 画面外へはみ出してよい

**PC・スマホの区別なく、格子は左へはみ出す前提で設計する。** ビューポートに収めるための縮小・折り返し変更・段組み変更は一切行わない。

- 字の大きさは**可読性から決める**（画面幅から逆算しない）。結果として紙面が画面より広くなるのは正しい状態。
- はみ出し方向は**左**。縦組みで列が右から左へ進むため、未読領域は常に左にある。
- 左下の `←` は「左にまだ紙面がある」ことの表示であり、モックの意図をそのまま満たす。
- 移動はドラッグによるパン（PC でもスマホでも同一の操作）。左右スクロールバーは出さない。
- 初期カメラ位置は**紙面の右上**、すなわち第 1 列の先頭。読み始めの位置に置く。
- パン可能な範囲は紙面の矩形にクランプする。無限に虚空へ流れていかないようにする。
- 縦方向（1 列 16 文字ぶん）は**等倍では**画面高に収める。**はみ出すのは横方向のみ**とする。これにより「1 列は必ず読み切れる」状態を保つ。
- **拡大は等倍を下限とする補助操作。** ホイール／ピンチで等倍〜4 倍。拡大するとカーソル（ピンチなら 2 点の中点）の下の一点を固定したまま寄り、視野が狭まったぶん縦にも送れるようになる。等倍へ戻せば縦の可動域は消え、上の「1 列は必ず読み切れる」既定に戻る。
- 拡大率は L0 のみが持つ。潜ると等倍へ戻す（L1 以降は大書であって紙面ではない）。

```
       ← 行の進行方向（右から左）

  行1  行2  行3  …
   ↓    ↓    ↓
  文字  文字  文字      ┐
  文字  文字  文字      │ 16 文字
  文字  文字  文字      │
   …    …    …        ┘
```

### 意味の区切りは L1 から

- **L0（ルート）では意味の区切りを一切見せない。** 格子は均質な紙面として提示する。
- 句としてのまとまりが現れるのは **L1 以降**。
- L0 での hover / フォーカスは、**一定範囲の文字だけが光る**表現とする。
  範囲は連続した文字インデックスなので、格子上では列をまたぐことがある。
  升目の途中で切れて次の列へ続く見え方をそのまま許容する（範囲を升目に合わせて調整はしない）。
- 光るのは文字のみ。升目の枠線や範囲を囲う図形は描かない。
- この「紙面は均質なのに、触れると意味の切れ目が浮かぶ」ギャップが L0 の体験の核になる。

### 句の範囲の持ち方

範囲は `kind: phrase` のノードが**全文に対する文字インデックス範囲**として持つ（→ [コンテンツモデル](#コンテンツモデル)）。
格子の座標は `index → (column, row)` の単純な写像で求まる。

列の切れ目は `content/sutra.txt` の**改行位置**に従う。1 行 = 1 列で、次の行は必ず新しい列の上端から始まる
（題名・「即説呪曰」・真言・「般若心経」がそれぞれ独立した列に立つ）。`COLS_PER_LINE = 16` は 1 列に収まる字数の
**上限**で、これを超える行だけが次の列へ折り返す。写像は `src/content/sutra.ts` の `GRID_CELLS` が持ち、
描画側（`Paper.tsx` / `PaperFallback.tsx`）は割り算をせずこの表を引く。逆引きは `indexAt(column, row)`。

## 遷移演出

深度をまたぐ演出。**潜るときと戻るときで非対称**にする。

### 潜る（`L0 → L1`、以降も同様）

1. フォーカスされた範囲の文字が明るさを保ったまま残る。
2. **それ以外の文字が粒子となって散開する。** 文字の形が解けて粒子群になり、外へ流れて消える。
3. 生き残った文字だけが、次の深度のレイアウト位置へ**連続的に移動・再配置**される。

要点は、生き残る文字が「消えて出直す」のではなく**同一の存在として移動し続ける**こと。
文字のアイデンティティが保たれることで、潜っても同じ紙面の続きにいる感覚が維持される。

### 戻る（`L1 → L0`、以降も同様）

1. **今ある文字はそのまま残り、** 元のレイアウト位置へ連続的に再配置される（消さない）。
2. それと並行して、**粒子がフェードインしながら凝集し、周囲の文字を形作る。**
3. 粒子が文字の形に収束しきったところで、通常のグリフ表示へ引き継ぐ。

散開の逆再生ではない。**散開は「解けて飛ぶ」、復帰は「無から浮かび上がる」** という別の運動にする。
戻る操作で紙面が虚空から現像されてくる感覚が、写経の紙面のメタファーに合う。

### 実装メモ

| 項目 | 方針 |
|---|---|
| 粒子のホームポジション | ビルド時に前計算した粒子サンプル座標（→ [グリフの扱い](#グリフの扱い演出の核)） |
| 生き残る文字 | 粒子系ではなく**メッシュのまま** spring 補間で移動させる。粒子化しない |
| 散開する文字 | メッシュを消し、同じ位置から粒子を発生させて外向きに流す |
| 復帰する文字 | 粒子を散開時とは別の分布（画面全体からの薄い流入）から凝集させ、収束後にメッシュへ差し替える |
| 差し替えの隠蔽 | 粒子 → メッシュの切替は、両者を数フレーム重ねてクロスフェードして隠す |
| 入力の無効化 | 演出中は `zooming-in` / `zooming-out` 相にあるため入力を受けない（→ [状態機械](#状態機械)） |

### 性能ティアごとの落とし所

演出の**筋書きは全ティアで共通**にし、粒子数と表現の粒度だけを落とす。

| ティア | 散開・凝集の表現 |
|---|---|
| `Tier 1`（WebGPU） | 数十万粒子。コンピュートシェーダで 1 文字あたり数千点を個別に動かす |
| `Tier 2`（WebGL2） | 粒子数を 1 桁落とす。頂点シェーダの時間ベースアニメで散開・凝集を表現する。1 文字あたりの点数を減らし、密度の低さを不透明度とサイズで補う |
| `Tier 3`（WebGL なし） | 粒子表現なし。DOM のフェードイン／アウトのみ。文字の再配置は CSS transition で行う |

## デザイントークン

モックから抽出した値（近似値。実装時に微調整する前提）。

```css
:root {
  /* 面 */
  --bg:            #050505;  /* ほぼ黒。完全な #000 ではなく僅かに浮かせる */
  --vignette:      radial-gradient(ellipse at 50% 50%, #0a0a0a 0%, #000 85%);

  /* 文字 */
  --ink:           #f2f0ec;  /* 大書・筆文字。わずかに温かい白 */
  --text:          #d8d5cf;  /* 解説本文 */
  --text-dim:      #8e8a84;  /* 読みガナ・梵語・補助 */
  --rule:          #b98a4a;  /* img_01 の区切り罫。淡いオレンジ */

  /* 状態 */
  --focus:         #ffd08a;  /* hover / 選択の琥珀 */
  --focus-glow:    #ffb85c;  /* グローの芯 */

  /* 図形 */
  --stroke:        rgba(242,240,236,.55);  /* 円相・矩形枠・連結線 */
  --stroke-hover:  var(--focus);
}
```

- 彩度は全体で極端に低い。琥珀のアクセント以外に有彩色を出さない。
- グローは 2 段（近距離の強い滲み + 遠距離の弱い滲み）。DOM 側は `text-shadow`、WebGPU 側は
  ビルド時に焼いた**字ごとの符号付き距離場（SDF）**を引いて、輪郭からの距離で減衰させる（→ [グリフの扱い](#グリフの扱い演出の核)）。
  板の中心から放射させると字が違っても同じ丸い光になり、「字が光っている」ではなく「字の裏に電球がある」絵になる。
- 白の使い分けは 3 段（`--ink` > `--text` > `--text-dim`）。この階層が奥行きを作っている。

### タイポグラフィ

| 用途 | 書体 | 組み |
|---|---|---|
| 大書・図中の文字 | 筆文字（`assets/svg/` の 111 字を使用） | 縦組み。WebGPU レイヤーで描画 |
| 解説本文・サマリー | 明朝系（可読性優先） | `writing-mode: vertical-rl`。DOM レイヤー |
| 読み・梵語 | 同上・極小 | 縦組み・字間広め。ラテン翻字は縦中横にせず縦に流す |
| 現在位置インジケータ | ゴシック or 明朝（可読性優先、筆文字にしない） | 縦積み |

## アーキテクチャ

### 2 レイヤー合成

| レイヤー | 内容 | 技術 |
|---|---|---|
| WebGPU レイヤー（Canvas） | 大書の筆文字グリフ、粒子の散開・再凝集、ゆらぎ、hover 発光、円相・連結線の描線 | three.js `WebGPURenderer` + TSL、@react-three/fiber v9 |
| DOM レイヤー（HTML オーバーレイ） | 縦書きの長文解説、サマリー、読み・梵語、読み上げボタン、現在位置インジケータ、左矢印 | `writing-mode: vertical-rl` + motion |

数百字級の縦組みを WebGL で描くと品質・実装コスト・アクセシビリティのすべてで損をするため、
**組版は DOM、絵は GPU** に振り分ける。筆文字は SVG パスがあるので GPU 側の素材として最適。

**カメラのドラッグ移動は両レイヤーを同期させる。** ワールド座標系のコンテナを 1 つ定義し、
three.js のカメラと DOM オーバーレイの `transform: translate3d(...)` に同じ変換を適用する。
`drei` の `<Html>` ではなくワールド固定の独自オーバーレイにする（長文組版の制御性、およびフォールバックの都合）。

### 技術スタック

| 領域 | 採用 | 備考 |
|---|---|---|
| ビルド | Vite + TypeScript | SSR 不要。静的ホスティング（Cloudflare Pages 等） |
| 3D | three.js `WebGPURenderer` + TSL / r3f v9 | `gl: async (props) => { const r = new WebGPURenderer(props); await r.init(); return r }` |
| 状態 | Jotai | 現在ノード、遷移フェーズ、設定（音量等） |
| 遷移制御 | 小さな手書き FSM（or XState 軽量利用） | 上述の相を明示的に持つ |
| アニメーション | TSL（粒子）+ spring 補間（カメラ・DOM） | DOM 側は motion |
| コンテンツ | YAML（グラフ）+ Markdown（解説） | `import.meta.glob` + ビルド時パース、zod で検証 |
| 音声 | Web Audio API 直 | 1 トラックを常時ループ。階層による切替なし。初回はユーザー操作で開始 |

`drei` への依存はほぼ不要（WebGL 前提のコンポーネントが混ざるため避ける）。

### グリフの扱い（演出の核）

各文字について、**ビルド時に** SVG から 3 つの表現を生成しておく。ランタイムで SVG をサンプリングしないのがスマホ性能上の要点。

1. **メッシュ** — `SVGLoader` でパス → 三角形分割。通常表示・hover 発光用。フィルは TSL マテリアルで墨のかすれ・にじみを付与。
2. **粒子サンプル** — 塗り領域から数千点／字をサンプリングした座標配列（バイナリで同梱）。コンピュートシェーダの「ホームポジション」として使い、散開 ⇄ 再凝集・文字間モーフをすべて GPU 側で補間。
3. **符号付き距離場** — 字面より一回り広い正方セル（64×64 / 字）に、輪郭からの距離を焼いた 8bit のアトラス。hover 発光の滲みは、板の中心からの半径ではなくこの距離で減衰させる。**光が字の形から出ている**ように見えるかはここで決まる。

111 字 × 4,000 点 ≒ 45 万点。WebGPU コンピュートで十分回る規模。

### 性能ティア

| ティア | 条件 | 内容 |
|---|---|---|
| Tier 1 | `navigator.gpu` あり | フル演出。数十万粒子、コンピュートシェーダ |
| Tier 2 | WebGL2 のみ | 粒子数を 1 桁落とし、頂点シェーダの時間ベースアニメへ切替。中位機のスマホはここ |
| Tier 3 | WebGL 不可 | Canvas を一切マウントせず、DOM レイヤー + CSS フェードのみ |

- 判定順は `navigator.gpu` → WebGL2 コンテキスト取得試行。
- `devicePixelRatio` は 1.5〜2 で上限キャップ。
- 起動後数秒のフレームタイム計測で粒子数を動的に下げ、機種差を吸収する。
- Tier 3 は 2 レイヤー構成の帰結として「WebGPU レイヤーを外すだけ」で自然に得られる。

### ターゲット環境

- 最新のスマホ・タブレット・Chrome のみを対象とする。
- **スマホ対応は必須要件。** ただし左右スクロールではなく、**ドラッグでカメラのフレームを移動**させる操作にする。
- パン可能な方向は左矢印（`←`）の明滅で示す。

## コンテンツモデル

グラフ構造は YAML、解説文は Markdown + frontmatter。**経文本文・解説文本文はすべてここに置き、コード側に埋め込まない。**

### `content/sutra.txt`

全文のプレーンテキスト。**文字インデックスの唯一の基準**となるため、以下を厳守する。

- **改行は L0 の列の切れ目**として使う。1 行 = 1 列で、1 行は `COLS_PER_LINE = 16` 字以内に収める。
- 行の途中に空白・約物を入れない（ローダが除去するため `range` はずれないが、その升は空かずに詰まる）。
- 文字を追加・削除するとすべての `range` がずれるため、変更は `range` の一括見直しとセットで行う。
- 含まれる文字種は `assets/svg/` の 111 字に限る（ビルド時に検証）。

### `content/graph/*.yaml`

```yaml
id: goun                 # 一意のスラッグ（ローマ字）
kind: term               # sutra | phrase | term
label: 五蘊              # 表示ラベル（大書に使う文字列）
reading: ごうん
sanskrit:
  text: pañca-skandha    # ラテン翻字
  kana: パンチャ・スカンダ
summary: …               # 右中段の短い定義（数十字）
parent: shoken-goun-kaiku
children: [shiki-rupa, ju, so, gyo, shiki-vijnana]
related: [juuhachi-kai]  # 隣接ノード（将来用）
layout: circle           # none | circle | column
range: [12, 17]          # 全文に対する文字インデックス範囲（半開区間 [start, end)）
audio: goun.m4a          # 読み上げ音源（assets/voice/ 配下のファイル名）
```

- `layout` は**ノード側が持つ**。円相か縦連結かは概念ごとに異なるため、描画側で決めない。
- `label` に含まれる各文字は `assets/svg/` に対応する SVG が存在しなければならない。

#### `range` — 全文に対する文字インデックス範囲

- `content/sutra.txt` の先頭を `0` とする**半開区間 `[start, end)`**。`end - start` が文字数になる。
- `kind: phrase` は必須。`kind: term` も、全文中に対応する連続文字列があれば持つ（例: `五蘊` は句の中の 2 文字）。
- 全文中に現れない概念ノード（`前五識`・`阿頼耶識` など、経文に登場しない用語）は `range` を**持たない**。
  `range` の有無が「格子上にハイライトできるか」を決める。
- ルート（`kind: sutra`）は `range: [0, <全文長>]` とする。

ビルド時に次を検証する。

- `sutra.txt.slice(start, end) === label`（`range` を持つノードのみ）
- 親が `range` を持つなら、子の `range` は親の範囲に**内包**されていること
- `range` が全文長を超えないこと

### `content/docs/*.md`

```markdown
---
id: goun
---

（長文解説の本文。DOM レイヤーで縦書き組版される）
```

### ビルド時検証（zod + 自作チェック）

CI で落とすべき条件：

- `parent` / `children` / `related` の参照切れ
- 親子関係の非対称（`a.children` に `b` があるのに `b.parent` が `a` でない）
- 到達不能な孤立ノード
- `id` に対応する `docs/*.md` の欠落
- `label` の構成文字に対応する SVG の欠落
- `layout: none` なのに `children` を持つ（またはその逆）

## ナビゲーション

### URL 同期

- `/#/goun/shiki` のようにノードパスを URL に載せる。初期はハッシュルーティングで十分。
- **ブラウザバック = ズームアウト** に割り当てる。共有リンクとしても機能する。

### 現在位置インジケータ（モックには無い追加要件）

- 画面端に **1 本の白い縦線**を引き、その横に先祖ノードを**縦に積み上げる**。
- 文字は**筆文字ではなく通常書体**（可読性優先）。大書との役割を明確に分ける。
- 各項目はクリック可能。押すとその階層まで一気にズームアウトする。
- 深さ = 潜水深度のメタファー。下端に薄い深度線を引くと『深般若』の名に合う。

### 左矢印

- モックの「左にコンテンツがある」印はそのまま採用。
- **PC・スマホ共通でドラッグによる左パン。** 操作を出し分けない（→ [画面外へはみ出してよい](#画面外へはみ出してよい)）。
- パン可能な方向を矢印の明滅で示す。左端に到達したら明滅を止める。
- 拡大中はドラッグが縦にも効く。矢印は左端の判定だけを見るので拡大しても意味は変わらない。

### 音声

音は**ノイズにならないこと**を最優先の制約とする。存在を主張せず、環境として鳴っている状態を保つ。

#### BGM

- **1 トラックを最初から最後までループ再生し続ける。** 階層に応じたトラック切替やクロスフェードは**行わない**。
- 階層が変わっても音は途切れず、同じ場が続いている感覚を保つ。
- 自動再生制限があるため、**初回はユーザー操作をトリガに開始**する（最初のクリック／タップ）。
- ループ点は無音を挟まずシームレスに繋ぐ。継ぎ目でクリックノイズが出ないよう、ループ境界で数十 ms のクロスフェードをかける。
- 音量は控えめな既定値から始め、ユーザーが下げ切れる（ミュート可能な）UI を用意する。

#### 配信方式（ストリーミングの可否）

**ストリーミングは可能。** `<audio>` 要素は HTTP Range によるプログレッシブダウンロードで再生でき、
`MediaElementAudioSourceNode` 経由で Web Audio グラフに載せられる（ダッキングやフィルタも効く）。
静的ホスティングのままで動作し、専用のストリーミングサーバは不要。

**ただし継ぎ目の問題がある。** 素朴に `<audio loop>` を使うと、MP3 / AAC が持つエンコーダ遅延とパディングにより
**ループ境界に無音の隙間が入る**。「ノイズにならない」という最優先制約に直接反するため、これは採れない。

サンプル精度でギャップレスにできるのは `decodeAudioData` + `AudioBufferSourceNode.loop` だが、これは全長デコードが前提。
参考として、現行の `sample_music_01.mp3`（7.7MB / 128kbps 換算で約 8 分）を全長デコードすると
float32 ステレオ 44.1kHz で **約 170MB** のメモリになり、モバイルでは通らない。

したがって方式は次の 2 案に絞られる。

| 案 | 方式 | ループ品質 | メモリ | 実装 |
|---|---|---|---|---|
| **A（推奨）** | ループ素材を 60〜120 秒に作り、Opus/WebM で 1〜2MB に収めて全長デコード。`AudioBufferSourceNode.loop = true` | **完全ギャップレス**（サンプル精度） | 120 秒で約 42MB。許容範囲 | 最も単純 |
| B | `<audio>` を 2 つ用意し、末尾数秒で交互にクロスフェード。ストリーミングのまま繋ぐ | 継ぎ目は隠れるが、同じ地点に戻る感覚は薄れる | 小 | 素直 |

- 案 A ならストリーミング自体が不要になる。瞑想 BGM は長尺の展開を要さないため、これが最も筋が通る。
- 長尺の素材を維持したい場合は案 B。
- MSE による自前チャンク供給も理論上可能だが、この用途には過剰。採らない。
- **どちらを採るかは未決**（→ [未決事項](#未決事項)）。素材の尺の決定と同時に確定させる。

#### 効果音

- ズーム遷移に `woosh` を重ねる。BGM より明確に小さく、単発で減衰しきる。
- 連続操作で重なって濁らないよう、同一 SFX の同時発音数を 1〜2 に制限する。

#### 読み上げ

- **収録音声を使う。** 制作者本人が読み上げて録音したファイルをノードごとに持つ。TTS は使わない。
- ファイルは `assets/voice/` に置き、YAML の `audio` フィールドで参照する。
- 「読み上げ」ボタン（右上）で再生。再生中はボタンが状態を示し、もう一度押すと停止する。
- 再生中は BGM を数 dB だけ絞る（ダッキング）。BGM を止めはしない。
- 音源が未収録のノードでは、ボタンを非表示にする（無効状態で置かない）。

#### 収録・エンコードの前提

| 項目 | 方針 |
|---|---|
| 収録 | 制作者本人。ノード 1 つ = ファイル 1 つ |
| 命名 | ノードの `id` と一致させる（`goun.m4a` 等）。YAML の `audio` で明示参照もできる |
| 形式 | 読み上げは AAC（`.m4a`）。BGM も配信用に圧縮する |
| 前処理 | 無音のトリム、ラウドネス正規化、ノイズ除去。読み上げ間で音量感を揃える |

### 円相（`assets/pattern/circle.svg`）の扱い

`layout: circle` の外周はこの素材を使う。手続き的生成はしない。形式がグリフ SVG と異なるため、専用の読み込み経路が必要。

| 項目 | 値 | 対応 |
|---|---|---|
| 生成元 | potrace 1.15 によるトレース | — |
| `viewBox` | `0 0 1273 1280` | ほぼ正方形だが**正確な正方形ではない**。アスペクトを保って配置する |
| `fill` | `#000000` | **黒で書かれている。** 描画時に `--ink` へ置換が必要 |
| `transform` | `translate(0,1280) scale(0.1,-0.1)` on `<g>` | Y 軸が反転している。パース時に適用を忘れると上下が逆になる |
| パス構成 | 主となる長大なパス 1 本 + 微小な断片パス **約 40 本** | 断片は筆のかすれ・飛沫。**間引かずに全て使う**（質感の源） |
| 形状 | 正円ではなく、線幅が場所により変化する閉領域（塗り） | ストロークではなく塗り図形として扱う |

- ビルド時に `scripts/build-glyphs.ts` と同じ経路でメッシュ化し、グリフと同様に TSL マテリアルを適用する。
- 円相も**粒子化の対象にする**と、円が散って再凝集する演出がそのまま得られる。断片パスが多いので粒子サンプル数は面積比で配分する。
- 出現アニメーションは、筆の運びに沿って現れる（円弧に沿った線形の露出）のが自然。パスを角度でソートしておくと実装しやすい。

| hover のフェードと滲み | 発色・減光・グローを 0.4 秒（`FOCUS_FADE`）かけて渡す。滲みは SDF ベース（`createGlowMaterial`）で、届く距離は `GLOW_NEAR` / `GLOW_FAR`、濃さは呼び出し側（`L0` は `GLOW_STRENGTH`、大書は `GLOW_OPACITY`）。値は画面で見て詰める前提の初期値 |

### 未着手 — ここが残作業の本体

**[遷移演出](#遷移演出)が繋がっていない。** 現状は相の管理（900ms で `settled`）と粒子データの用意までで、
`settled` の瞬間に `L0` と `L1` の描画が差し替わる。README が要求している核心が抜けている。

- 散開と凝集の分布は別々に用意してあり（逆再生にしない）、この 2 点が解ければ筋書きは通る。

### 実装時に決めたこと（README に書かれていなかった判断）

後から読む人が「なぜそうなっているか」を追えるように残す。**設計を変えたつもりはなく、隙間を埋めた記録である。**

| 判断 | 理由 |
|---|---|
| **`layout: none` でも `phrase` は子を持ってよい** | `layout` が支配するのは「子の**関係図**」であって遷移そのものではない。[初期スコープ](#初期スコープ)の経路自体が句 → 句の下降を含むため、ここを CI で落とすと成立しない。検証は「`term` が `layout: none` で子を持つ」場合のみ落とす |
| **根（`kind: sutra`）は `range` と `label` を突き合わせない** | 根の `range` は全文を指すが、`label` は大書用の題名であって全文ではない |
| **識の子を六識（眼耳鼻舌身意）にした** | `layout: column` には子が要る。前五識・末那識・阿頼耶識は `assets/svg/` に字が無く大書できないため、在庫のある六識を採った |
| **可動域はビューポート依存にした** | 紙面は縦 16 升が画面高に収まるよう描かれるので、横がはみ出すかは画面のアスペクト比で決まる。**縦長のスマホでは必ずはみ出し、16:9 の PC では収まりきる。** 定数ではなくリサイズのたびに実測から引き直す |
| **拡大の下限は等倍** | 縮小まで許すと「縦 16 升が画面高に収まる」という紙面の前提が崩れ、可動域・行送り・字の大きさの根拠が全部揺れる。寄る方向だけを足した |
| **Tier 3 の紙面は拡大しない** | DOM の段組みなので `transform: scale` では字の詰まり方が破綻し、ワールド座標の対応も取れない。Tier 3 ではパンだけを許す（`usePanZoomGesture` の `allowZoom`） |
| **パンの捕捉はドラッグと判ってから** | `pointerdown` で即 `setPointerCapture` すると `pointerup` がキャンバスに届かず、クリックが成立しなくなる。6px 動いてから捕捉する |
| **hover の発光は `instanceColor` を使わない** | `WebGPURenderer` のノードマテリアル経路で期待どおりに効かなかった。インスタンス属性 + TSL で書き、Tier 1 / Tier 2 で同じ結果になるようにした |
| **当たり判定は `visible={false}` にしない** | 不可視のオブジェクトはレイキャストの対象から外れる。透明マテリアルで置く |
| **BGM は案 B を既定にした** | 現行素材が 8 分あり、案 A（全長デコード）はモバイルで通らない。1 定数（`BGM_STRATEGY`）で案 A へ切り替えられる形にしてある。**未決事項は未決のまま** |
| **`content/sutra.txt` は空白を除去して正規形にする** | ファイルを手で整形しても `range` がずれないようにするため。インデックスの基準は正規形 |
