# 遷移演出

深度をまたぐ演出。**潜るときと戻るときで非対称**にする。逆再生にはしない。

## 持ち越される字 — 演出の軸

深度をまたぐとき、**薄れも現れもしない字がちょうど 1 ノードぶんだけある。** 選んだノードの字がそれで、潜るときは「L0 で選んだ句 → 次の見出し」「図の中の子 → 次の大書」、戻るときはその逆をたどる。この字だけが出発点から行き先へ動きながら描かれ、それ以外の字は（フォーカス範囲の内外を問わず）すべて出入りに乗る。

- 対応づけは**同じノードに属する字を同じ順に並べて 1 対 1** で取る。数が合わなければ持ち越しを諦め、全部が粒子になる。
- 持ち越しの字は紙面・大書の側では伏せられ（`carry.ts` の id と `materials.ts` の `carryOpacity`）、遷移の終わりに行き先の描画へそのまま引き継がれる。改めて現れさせない。
- **生き残る字は「フォーカス範囲の全字」ではなく「選んだ 1 ノードの字」。** 範囲で決めると、潜り先で大書にならない字まで残ってしまう。

## 潜る（`L0 → L1`、以降も同様）

1. 選んだノードの字が明るさを保ったまま残る。
2. **それ以外の文字が粒子となって散開する。** 文字の形が解けて粒子群になり、外へ流れて消える。
3. 持ち越された字が、次の深度のレイアウト位置へ**連続的に移動・再配置**される。

文字のアイデンティティが保たれることで、潜っても同じ紙面の続きにいる感覚が維持される。

## 戻る（`L1 → L0`、以降も同様）

1. **今ある文字はそのまま残り、** 元のレイアウト位置へ連続的に再配置される（消さない）。
2. それと並行して、**粒子がフェードインしながら凝集し、周囲の文字を形作る。**
3. 行き先の字は**最初から濃さ 0 で置いてある。** 凝集と同じ時間で濃くなり、粒子が形に収まる時点で出そろう。
4. 粒子は**収まってから遅れて引く。** 光が字に重なったまま薄れるので、粒子とメッシュの切替が絵として見えない。

3 と 4 が要点。「凝集しきってから字を出す」順にすると、そこで必ず間が空く。字は先に置いて薄いまま待たせ、光のほうを後から引かせる。

**散開は「解けて飛ぶ」、復帰は「無から浮かび上がる」** という別の運動にする。戻る操作で紙面が虚空から現像されてくる感覚が、写経の紙面のメタファーに合う。

## 時間の設計

尺とカーブは 1 か所（`scene/Transition.tsx`）が持ち、粒子・字・カメラ・DOM がすべてそこから引く。

| 項目 | 値 / 方針 |
|---|---|
| 演出の尺 | `TRANSITION_MS = 1700` |
| 補間カーブ | 5 次（smootherstep）の `ease()`。両端で加速度も 0 になり、動き出しに角が立たない |
| カメラ | **持ち越しの字と同じ時計・同じカーブで動かす。** spring の追従にすると、ワールドでは直線に動く字が画面上で寄り道して見える |
| 字の出入り | 消えるのは 2 乗のカーブで素早く。現れるのは着地を見せきってから（`APPEAR_DELAY_MS = 500`） |
| 字の現れ（L0 へ戻るとき） | 例外。遅延を挟まず、進行度 `ENTER_FROM = 0.5` から尺いっぱいかけて濃くする。**粒子の凝集と同じ時間で立ち上げる** |
| 粒子の尺 | **字とは別に持つ。** 揃えると字と粒子が同時に薄れ、「字が解けて粒になった」順序が出ない |
| 粒子の余韻 | 演出の**あと**に伸びる `PARTICLE_FADE_MS = 520`。凝集しきった光はここで引く。位置は home に着いたまま濃さだけを落とす |
| DOM オーバーレイ | 同じ遅延を引いて字に追随する |

## 実装メモ

| 項目 | 方針 |
|---|---|
| 粒子のホームポジション | ビルド時に前計算した粒子サンプル座標（→ `ink-visuals`） |
| 持ち越される字 | 粒子系ではなく**メッシュのまま**補間で移動させる。粒子化しない |
| 散開する文字 | メッシュを消し、同じ位置から粒子を発生させて外向きに流す |
| 散開の運動 | 上向きに偏らせる（真上は真下のちょうど 2 倍飛ぶ）。終わりぎわに浮き上がる等加速度 + 粒ごとにずれた横揺れ。**煙が立ちのぼる向き**を作る |
| 粒の形 | 円形（板の UV から抜く）。四角い粒は紙の上の塵に見えない |
| 復帰する文字 | 粒子を散開時とは別の分布（画面全体からの薄い流入）から凝集させ、収束後にメッシュへ差し替える |
| 差し替えの隠蔽 | 粒子 → メッシュの切替は両者を重ねて隠す。字は凝集と同じ時間で立ち上げ、粒子は演出のあとに引く |
| 濃さのユニフォーム | **深度ごとに 1 本ずつ**（`paperOpacity` / `nodeOpacity`）。戻りぎわは大書と紙面が同時に画面へ居るので、1 本では片方を薄めながらもう片方を出せない |
| 描画経路 | **`Points` ではなく `Sprite` のインスタンシング。** `PointsNodeMaterial` の `sizeNode` は `Points` に対して読まれない（WebGPU の点は 1px 固定、WebGL2 経路は `material.size` を見る）ため、粒ごとの大きさが要るならこの経路しかない |
| 入力の無効化 | 演出中は `zooming-in` / `zooming-out` 相にあるため入力を受けない（→ `navigation-fsm`） |
| 拡大率 | 潜るときは等倍へ戻す（→ `pan-zoom`） |

## 面の用意はやり直さない — 演出が固まる原因

**紙面（L0）は一度組んだら畳まない。** 潜っているあいだも置いたままにし、描かず・フレームの計算もせず・当たり判定にも出さないだけにする（`Paper` の `live`）。マウントし直すと、90 字ぶんのマテリアルと描画オブジェクトの用意をその 1 フレームで払うことになり、そこで固まる。**どのタイミングでマウントしても固まる場所が変わるだけ**で、演出の終わりに置けば着地が跳ね、頭に置けば動き出しが跳ねる。捨てなければ three はシェーダのプログラムを持ち続けるので、戻ってきても組み直しが起きない。

紙面のマテリアルは**字ごとではなく紙面で 1 本**にする。ムラの種・フォーカス量・持ち越しはすべてインスタンス属性で持たせてあるので、シェーダそのものは字によらず同じ。

**固まったり固まらなかったりする場合、疑うのはマテリアルを作り直しているところ。** TSL が吐くシェーダのソースには属性の通し番号が入るので、作り直すたびにソースが別物になり、ブラウザのプログラムキャッシュに当たったり当たらなかったりする。確率的に見えるのはこれによる。

シェーダの用意だけを別スレッドへ逃がすことはできない。WebGL / WebGPU のコンテキストはキャンバスを持つスレッドのものなので、`OffscreenCanvas` でレンダラごとワーカーへ移すしかなく、2 レイヤー合成とポインタ入力を組み直すことになる。**先に作って捨てない**のが答えで、ほんとうに先読みが要るときの手は読み込み中の `renderer.compileAsync(scene, camera)`。

## 性能ティアごとの落とし所

演出の**筋書きは全ティアで共通**にし、粒子数と表現の粒度だけを落とす（→ `perf-tier`）。
