# パンと拡大

**パンは深度で別勘定にする。** L0 は `panXAtom`（＋拡大・縦送り）、**L1 以降は `nodePanXAtom` の左右だけ**。

## 共通の原則

- 移動は**ドラッグによるパン**。PC でもスマホでも同一の操作にし、出し分けない。左右スクロールバーは出さない。
- **パンは 1 つの atom に集約する。** カメラと CSS 変数 `--pan-px` が同じ値を読む。2 レイヤー合成（組版は DOM、絵は GPU）で層がずれないための唯一の担保。
- **補間は 1 箇所だけに置く。** ばねは atom 側に持たせ、カメラは値をそのまま読む。カメラ側でも補間すると 2 度掛かり、**大書だけが DOM の本文に遅れて 2 つの層がずれて見える**（`useNodePanSpring` / `CameraRig`）。
- パン可能な範囲はクランプする。無限に虚空へ流れていかないようにする。
- パン可能な方向は左矢印（`←`）の明滅で示す。送り先が無い画面では出さない（→ `navigation-fsm`）。

## L0（紙面）

- はみ出し方向は**左**。縦組みで列が右から左へ進むため、未読領域は常に左にある（→ `paper-grid`）。
- 初期位置は紙面の右上（第 1 列の先頭）。
- **紙面が画面に収まる画面では中央ぞろえで固定**し、可動域を消す。
- **起動直後の 1 フレームは補間しない。** 読み始めの位置へ補間で寄せると、紙面が中央から右へ流れて見える。初回はカメラごと飛ばし、窓の寸法から出した半幅で最初のフレームから正しい位置に描く。

### 拡大（L0 のみ）

- **等倍を下限とする補助操作。** ホイール／ピンチで等倍〜4 倍。
- 拡大するとカーソル（ピンチなら 2 点の中点）の下の一点を固定したまま寄り、視野が狭まったぶん**縦にも送れるようになる**。等倍へ戻せば縦の可動域は消え、「1 列は必ず読み切れる」既定に戻る。
- **縮小は許さない。** 縮小まで許すと「縦 1 列が画面高に収まる」という紙面の前提が崩れ、可動域・行送り・字の大きさの根拠が全部揺れる。寄る方向だけを足した。
- 拡大率は L0 のみが持つ。潜ると等倍へ戻す（L1 以降は大書であって紙面ではない）。
- **Tier 3（DOM 紙面）では拡大しない。** DOM の段組みなので `transform: scale` では字の詰まり方が破綻し、ワールド座標の対応も取れない。パンだけを許す（`usePanZoomGesture` の `allowZoom`）。

## L1 以降

- 狭い画面では本文（縦組みの解説）が画面の外へ出る。**収めるための切り詰めや段組みの変更はせず、同じドラッグで左右にだけ**送れるようにする。
- **拡大も縦送りも持たない**（大書の高さは画面高で決め打ってある）。
- 送れる幅は本文・サマリーの左端の実測から引き、左端が画面に入り切ったところで止める。

## 可動域の求め方

- **可動域はビューポート依存。** 紙面は縦 1 列が画面高に収まるよう描かれるので、横がはみ出すかは画面のアスペクト比で決まる。**縦長のスマホでは必ず左へはみ出し、16:9 の PC では収まりきる。** 定数化せず、リサイズのたびに実測から引き直す。
- **L1 以降の可動域は DOM の実測から引く。** 本文の列数は組版の結果なので、ワールド座標の計算では出せない。
- **`offsetLeft` で読む**（`getBoundingClientRect` ではなく）。パンは transform で当てるため、rect で測ると送った量が次の可動域に混ざる。

## ドラッグの捕捉

**`setPointerCapture` は `pointerdown` 即時ではなく 6px 動いてから。** 即時に捕捉すると `pointerup` がキャンバスに届かず、クリックが成立しなくなる。

## 関連

- 紙面の格子とはみ出しの根拠 → `paper-grid`
- 大書がはみ出す画面での視野送り（`nodePanX`）→ `node-screen`
- 遷移中は入力を殺す → `navigation-fsm`
