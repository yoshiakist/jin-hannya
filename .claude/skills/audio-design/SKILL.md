# 音声

音は**ノイズにならないこと**を最優先の制約とする。存在を主張せず、環境として鳴っている状態を保つ。

## BGM

- **1 トラックを最初から最後までループ再生し続ける。** 階層に応じたトラック切替やクロスフェードは**行わない**。
- 階層が変わっても音は途切れず、同じ場が続いている感覚を保つ。
- **鳴らす前に断る。** 起動のロゴを書き上げた（あるいは飛ばされた）ところで、字の下に横組みで「本サイトはBGMが流れます」と小さく出し、**承知／静寂**の 2 つを置く。どちらかが押されるまで経文は滲み出さず、ロゴも薄れない（→ skill `ink-visuals`）。ロゴを持たない入り方（深いパスの直接ロード・Tier 3・`prefers-reduced-motion`）でも同じ断りを出す。音が流れるのは同じで、断りだけ省く理由が無い。
- **「静寂」は音を起こさない。** ミュートするのではなく `AudioContext` も `<audio>` も作らないので、**BGM の取得そのものが始まらない**。後からミュートを解いたときに初めて鳴り出す。
- **答えは `localStorage` に残す**（`jin-hannya:audio-consent:v1`）。二度目からは断りを出さず、覚えた答えのまま始める（「静寂」ならミュートで、音を起こさないまま）。**ただしロゴを出す入り方（根を直接開いたとき）でだけは毎回聞く。** ロゴを書き上げてから断りが出るのが一続きの流れで、そこだけ抜くと筆を置いた先が宙に浮く。
- 自動再生制限があるため、**開始はユーザー操作をトリガにする**（「承知」を押した操作がそのまま起点になる）。弾かれた場合だけ次のクリック／タップ／キー入力で試し直す。
- ループ点は無音を挟まずシームレスに繋ぐ。継ぎ目でクリックノイズが出ないよう、ループ境界で数十 ms のクロスフェードをかける。
- 音量は控えめな既定値から始め、ユーザーが下げ切れる（ミュート可能な）UI を用意する。
- **右上のミュート切り替えは、断りへの答えを言い直したものとして同じ記憶に書く**（伏せる = 静寂、戻す = 承知）。ここで伏せた読者を、次に開いたときまた断りから始めさせない。
- **上限ゲインを置く。** 音量 UI の 0〜1 はその範囲へ写し、スライダを振り切っても BGM が前に出ないようにする（現在は最大 1/4）。「ノイズにならない」制約を UI 操作で破れなくするための天井である。

### 配信方式（未決）

**ストリーミングは技術的に可能。** `<audio>` 要素は HTTP Range によるプログレッシブダウンロードで再生でき、`MediaElementAudioSourceNode` 経由で Web Audio グラフに載せられる（ダッキングやフィルタも効く）。静的ホスティングのままで動作し、専用サーバは不要。

**ただし継ぎ目の問題がある。** 素朴に `<audio loop>` を使うと、MP3 / AAC が持つエンコーダ遅延とパディングにより**ループ境界に無音の隙間が入る**。最優先制約に直接反するため採れない。

サンプル精度でギャップレスにできるのは `decodeAudioData` + `AudioBufferSourceNode.loop` だが、これは全長デコードが前提。現行の `sample_music_01.mp3`（7.7MB / 約 8 分）を全長デコードすると float32 ステレオ 44.1kHz で **約 170MB** になり、モバイルでは通らない。

| 案 | 方式 | ループ品質 | メモリ | 実装 |
|---|---|---|---|---|
| **A（設計上の推奨）** | ループ素材を 60〜120 秒に作り、Opus/WebM で 1〜2MB に収めて全長デコード。`AudioBufferSourceNode.loop = true` | **完全ギャップレス**（サンプル精度） | 120 秒で約 42MB。許容範囲 | 最も単純 |
| B | `<audio>` を 2 つ用意し、末尾数秒で交互にクロスフェード。ストリーミングのまま繋ぐ | 継ぎ目は隠れるが、同じ地点に戻る感覚は薄れる | 小 | 素直 |

- 案 A ならストリーミング自体が不要になる。瞑想 BGM は長尺の展開を要さないため、これが最も筋が通る。
- MSE による自前チャンク供給も理論上可能だが、この用途には過剰。採らない。
- **未決のまま。** 現行素材が 8 分あり案 A は通らないため、**実装は案 B を既定にしてある。** 切替は `BGM_STRATEGY` 1 定数。素材の尺の決定と同時に確定させる。

## 効果音

- ズーム遷移に `woosh` を重ねる。BGM より明確に小さく、単発で減衰しきる。
- 連続操作で重なって濁らないよう、同一 SFX の同時発音数を 1〜2 に制限する。

## 読み上げ

- **収録音声を使う。** 制作者本人が読み上げて録音したファイルをノードごとに持つ。**TTS は使わない。**
- ファイルは `assets/voice/` に置き、YAML の `audio` フィールドで参照する（→ `sutra-content`）。
- 「読み上げ」ボタン（右上）で再生／停止（→ `navigation-fsm`）。
- 再生中は BGM を数 dB だけ絞る（ダッキング）。**BGM を止めはしない。**
- 音源が未収録のノードでは、ボタンを非表示にする。

## 収録・エンコードの前提

| 項目 | 方針 |
|---|---|
| 収録 | 制作者本人。ノード 1 つ = ファイル 1 つ |
| 命名 | ノードの `id` と一致させる（`goun.m4a` 等）。YAML の `audio` で明示参照もできる |
| 形式 | 読み上げは AAC（`.m4a`）。BGM も配信用に圧縮する |
| 前処理 | 無音のトリム、ラウドネス正規化、ノイズ除去。読み上げ間で音量感を揃える |
