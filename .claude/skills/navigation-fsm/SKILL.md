# ナビゲーション

## 状態機械

ズーム中の多重クリックを殺すため、遷移相を明示的に持つ（`nav/fsm.ts`）。

```
idle ──hover──▶ hovered ──click──▶ zooming-in ──▶ focused
  ▲                                                 │
  └──────────── zooming-out ◀──back / breadcrumb ────┘
```

- **`zooming-in` / `zooming-out` の間は入力を無効化する。**
- `focused` からの子ノードへの遷移も同じ相を通す。
- 演出の尺は `scene/Transition.tsx` が持つ（→ `transition-fx`）。

## URL 同期

- `/goun/shiki/` のようにノードパスを**実パス**で URL に載せる。全パスは SSG（`app/[...path]/page.tsx` の `generateStaticParams`）で吐き、共有リンク・SEO・OGP が効く。範囲外のパスは 404。
- history は Next（`next/navigation`）に任せる。**自前の pushState / state.depth 管理はしない。** 潜る・戻るのどちらも「演出が idle に落ちたら `router.push`」で 1 段ずつ積む標準挙動（`nav/router.ts` の `useRouteSync`）。
- ブラウザバック／フォワードは pathname の変化として受け、深度を比べてズームイン／アウトの**演出付き**で状態へ反映する。遷移演出の最中に来た分は idle に落ちたとき拾い直す。
- **初期ノードは atom の初期値が URL から引く**（`nav/url.ts` の `initialNodeId`）。マウント後の effect で sync すると、「状態 → URL」の効果が同期前の根を見て `router.push('/')` する競合が起きる（実際に踏んだ）。
- **`router.push` は非同期で、pathname への反映まで数フレームの窓がある。** push したパスは `pushing` ref に控え、pathname の変化が自分の push の反映なら取り込むだけにする。この控えが無いと、窓の間に hover 等で効果が再実行されたとき古い pathname を外部遷移と誤認し、出発点へ逆再生で押し戻される（実際に踏んだ。発症は確率的）。
- id ⇄ パスの写像は `nav/url.ts`。`router.ts`（同期）と `atoms.ts`（初期値）の両方が使うので独立している。
- アプリ本体は `app/layout.tsx` に置いて全ルートで永続させる。page 側に置くと遷移のたびに再マウントされる（「面の用意をやり直さない」が崩れる）。各 page は metadata だけを担う。

## 現在位置インジケータ

モックには無い追加要件。

- 画面端に **1 本の白い縦線**を引き、その横に先祖ノードを**縦に積み上げる**。
- 文字は**筆文字ではなく通常書体**（可読性優先）。大書との役割を明確に分ける。字だけが要るので `labelText()` を通す（→ `sutra-content`）。
- 各項目はクリック可能。押すとその階層まで一気にズームアウトする。
- 深さ = 潜水深度のメタファー。下端に薄い深度線を引くと『深般若』の名に合う。

## このサイトについて（L0 の固定リンク）

- 経文の外の 1 枚（`kind: page` → `sutra-content`）への入口。**L0 の左上に据え、潜ったら引く。**
  潜った先の左上は現在位置インジケータの場所で、深さの線と外向きの案内を同じ角で競わせない（出る深度が排他なので重ならない）。
- 実体は素の `<a>`（`next/link`）。**クリックを自前で `dispatch` しない。** URL の変化として `useRouteSync` が拾い、
  ブラウザバックと同じ経路で演出付きの遷移になる。クローラと読み上げにも、隠しテキストを増やさずそのまま行き先が渡る。
- ただし `.overlay` は `ssr: false` の中なので静的 HTML には焼かれない。**行き先だけは `app/StaticDoc.tsx` にも置く**（L0 の隠し文書に 1 本）。
- 筆文字ではなく通常書体・小さめ・退いた色。紙面の外側の案内であって、経文の入口ではない。

## 左矢印

- モックの「左にコンテンツがある」印をそのまま採用。細い白線の矢印のみ、左下。
- **PC・スマホ共通でドラッグによる左パン。** 操作を出し分けない（→ `pan-zoom`）。
- パン可能な方向を矢印の明滅で示す。左端に到達したら明滅を止める。
- 拡大中はドラッグが縦にも効くが、矢印は左端の判定だけを見るので意味は変わらない。
- **L1 以降でも、本文が画面より広いときだけ出す。** 送り先が無い画面では出さない（示唆が嘘にならないようにする）。

## 読み上げボタン

- 画面右上。ピル型の枠線 + スピーカーアイコン。
- 再生中はボタンが状態を示し、もう一度押すと停止する。
- **音源が未収録のノードではボタンを非表示にする**（無効状態で置かない）。
- 再生仕様は `audio-design`。
