# L1 以降の画面（大書と子の図）

出典は `sample_image/img_01.png` `img_02.png` `img_03.png`（いずれも 16:9 / PC 想定）。

## 3 枚に共通するフレーム

縦書きの読み順に従い、**情報は右から左へ流れる**。右が「今いるノード」、左が「その詳説」。

| 位置 | 要素 | 備考 |
|---|---|---|
| 画面右端 | 現在ノードの大書（筆文字・縦組み） | 画面の主役。高さは画面の 60〜85% を占める |
| 大書のすぐ左脇 | 読み（かな）／梵語（カナ + ラテン翻字） | 極小サイズ・字間広め・縦組み |
| 右 1/4 付近 | 短い定義（サマリー） | 縦書き 2〜4 列、数十字 |
| 中央 | 子ノードの関係図 | `layout` によって配置文法が変わる |
| 左 1/3〜1/2 | 長文解説 | 縦書き多列。列は右から左へ進む |
| 右上 | 「読み上げ」ボタン | ピル型の枠線 + スピーカーアイコン |
| 左下 | 左矢印 `←` | 「左にまだコンテンツがある」の示唆。細い白線の矢印のみ |

- 背景はほぼ完全な黒。要素間の余白が非常に大きく、密度は低い。
- 大書と中央の図は、**白い細い引き出し線**で結ばれる（img_03 で顕著。水平 → 段差 → 図の外周へ接続）。親子関係を視覚的に明示する装置。
- カーソルは通常のマウスポインタ（カスタムカーソルではない）。

## レイアウト文法は 3 種類

`layout` は**ノード側の YAML が持つ**。描画側で決めない（→ `sutra-content`）。

| ヒント | 出典 | 見た目 |
|---|---|---|
| `none` | img_01 | 子の図を持たず、大書とテキストのみ。句レベルのノード |
| `circle` | img_03 | 筆で描いた**円相**の内側に、子要素を円周上へ均等配置 |
| `column` | img_02 | **角丸矩形**のノードを縦に並べ、細い縦線で直列に連結 |

### img_01 — 句レベル（`layout: none`）

- 大書は 1 ノード分の語ではなく**句全体**を 2 列に折り返して大書する。
- 大書の左に読みガナが縦一列。さらに左に短い訳文、その訳文の下端に**淡いオレンジ寄りの細い縦罫**が入り、区切りとして働く。
- 中央〜左は解説の多列組版のみ。図は無い。

### img_03 — 円相（`layout: circle`）

- 中央に、筆のかすれ・にじみを持つ**手描き感のある円**（正円ではなく、線幅が場所によって変わる）。直径は画面高の約 6 割。素材は `assets/pattern/circle.svg`（→ `ink-visuals`）。
- 円の内側に子要素の筆文字を円周上へ配置。頂点付近から時計回りに 1 つずつ。中心は空。
- hover 中の 1 要素だけが**琥珀色に発光**し、他は白のまま。発光は文字の輪郭からにじみ出るソフトグロー。
- 円の中心は画面中央よりやや左（右端の大書ぶんオフセットされている）。

### img_02 — 縦連結（`layout: column`）

- 角丸矩形（角丸半径は高さの約 1/4、スタジアム形に近い）を縦に等間隔配置。枠線は細い白、塗りは背景と同じ黒。
- 矩形どうしは**中央を通る 1 本の細い縦線**で連結（箱のあいだだけを繋ぐ）。
- hover 時は**文字と枠線の両方が琥珀色に発光**する（`circle` は文字のみの発光。枠を持つ図では枠も光らせる）。
- このノードでは大書からの引き出し線は見当たらない。`layout: column` では省略される、もしくは図の右上から伸びる仕様と解釈できる。

## 寸法は `world/node-layout.ts` が単独で持つ

大書と子の図の位置・大きさは `world/node-layout.ts` だけが持ち、描画（`NodeStage`）・遷移（`Transition`）・DOM の組版（`Overlay`）が同じ関数を引く。**ずれると遷移の継ぎ目で字が跳ね、オーバーレイが大書に重なる。** three に依存しない場所へ置くのはこのためである。

- **大書は列を上で揃える。** 長さの違う列が並んでも書き出しの高さが動かない。1 字の大きさはいちばん長い列から決めるので、句のように長い `label` でも必ず画面高に収まる。列の切れ目は `label` の空白（→ `sutra-content`）。
- **横に狭い画面では、大書がはみ出すぶんだけカメラごと右へ送る**（`nodePanX`）。大書だけを左へ寄せるのではなく視野ごと動かすので、大書と図の間隔＝右から左への情報の流れは変わらない。収まる画面では 0 を返し、設計どおり図が画面中央に来る。
- 大書の右に残す余白は**ワールド比ではなく px** で持つ。字の大きさは画面高から決まるため、横に狭い画面ほど大書は相対的に大きくなり、比で持つと読み（かな）の帯が潰れる。ただし幅に対する上限も置く。
- 大書の高さは画面高で決め打つ。L1 以降に拡大率は無い。

## DOM の位置決め — `overlayInsets`

読み・サマリー・本文は大書の実寸に合わせて置きたいが、大書は WebGPU レイヤーにあり DOM からは測れない。そこで `node-layout.ts` がカメラと同じ式でワールド座標を画面座標へ直し、**画面右端からの距離（px）**を 3 つの目印として渡す。

| 目印 | 意味 |
|---|---|
| `headlineRight` | 大書の右端。ここより右が読み（かな）の帯 |
| `headlineLeft` | 大書の左端。ここより左がサマリーと本文 |
| `diagramLeft` | 図の左端。図を持たないノードでは大書の左端と同じ（本文への制約にならない） |

- **組版そのものは CSS の役目**で、目印は CSS 変数として渡すだけ。間合いを変えるときは `.overlay` の `--reading-gap` / `--summary-gap` / `--doc-gap` を触る。
- 読みは大書の右、サマリーは大書の左、本文はさらにその左。
- **本文は `max-width` で切り詰めない。** 幅を掛けると狭い画面では列が消えて本文が読めなくなる。列数は本文の量が決め、画面に入らないぶんはドラッグで送る（→ `pan-zoom`）。
